# Language and Syntax

This guide derives the syntax from `src/lexer/token.rs`, the parsers in `src/parser/`,
and the AST structures in `src/parser/parser.rs`. The examples are minimal and do
not depend on external modules.

## Program and Script Modes

`parse_program` accepts only top-level declarations. `parse_script` accepts any
statement. Both generate a `PengUnit` with an initialization function; in program
mode, this function initializes globals, and in script mode it executes the
statements. Defined in `src/parser/parse_program.rs`, `src/parser/parse_script.rs`,
`src/generator/generate_program.rs`, and `src/generator/generate_script.rs`.

Valid program:

```penguin
const answer: int = 42

func add(a: int, b: int) -> int {
    return a + b
}
```

Valid script:

```penguin
var total = 40
total += 2
return total
```

Semicolons are optional at the end of declarations and expression/assignment
statements (`src/parser/parser_utils.rs` and
`src/parser/parse_expression_statement.rs`).

## Lexing and Literals

Identifiers start with `_` or a Unicode letter and continue with `_` or
alphanumeric characters. There are `//` and `/* ... */` comments, `"..."` strings,
and strings delimited by `#"..."#`. The lexer removes `\` when used as an escape
before the next character. Defined in `src/lexer/lexer.rs` and
`src/lexer/token.rs`.

| Form                               | Type/literal     | Example           |
| ---------------------------------- | ---------------- | ----------------- |
| `nil`                              | nil              | `nil`             |
| integer without suffix or with `i` | `int` (`isize`)  | `10`, `10i`       |
| suffix `u`                         | `uint` (`usize`) | `10u`             |
| suffix `b`                         | `byte` (`u8`)    | `255b`            |
| decimal or suffix `f32`            | `f32`            | `3.14`, `3.14f32` |
| suffix `f64`                       | `f64`            | `3.14f64`         |
| `true`, `false`                    | `bool`           | `true`            |
| string delimiter                   | `string`         | `"text"`          |

`_` separators are discarded in numbers, for example `1_000u`. Negative numbers
are unary expressions, not literals. Defined in `src/lexer/token.rs` and
`src/parser/parse_expression.rs`.

## Variables, Constants, and Types

Declarations use `var` or `const`, with an optional type hint. `var` can also be
declared without a value; `const` requires `=` and a value. The AST represents
mutability with `PengBinded::{Mutable, Immutable}`. Defined in
`src/parser/parse_declaration_statement.rs` and `src/core/binding.rs`.

```penguin
var count: int = 1
var pending: any
const name: string = "Penguin"
```

The type names accepted by the parser are `nil`, `int`, `uint`, `f32`, `f64`,
`byte`, `bool`, `string`, `any`, `type`, `mod`, `func`, `oper`, `thread`, custom
types, and vectors `[T]`. The runtime representation is `PengType` in
`src/core/typing.rs`; the parser is in
`src/parser/parse_type_expression.rs`.

Explicit conversion uses `as` and generates the `Convert` instruction:

```penguin
var wide = 12 as f64
```

The implemented conversions include numeric conversions, value-to-`string`
conversion in scalar cases, vector item checks, and structural checks for custom
types. The exact combinations and their errors are in `src/core/value.rs`.

## Functions

Functions have optionally typed parameters, an optional return type after `->`,
and a block body. The last parameter can be variadic with `...`; in a call, the
last argument can also be expanded with `...`. Defined in
`src/parser/parse_function_declaration_statement.rs` and
`src/parser/parse_function_params.rs`.

```penguin
func sum(a: int, b: int) -> int {
    return a + b
}

func first(items...) {
    return items[0]
}
```

Anonymous literals use `func (...) { ... }`
(`src/parser/parse_function_literal.rs`). `return` accepts an optional expression
and is compiled into `Return` (`src/parser/parse_return_statement.rs`,
`src/generator/generate_statement.rs`).

## Control Flow

Conditions are evaluated as `bool`; the VM returns `TypeMismatch` if it receives
another value. Executed in `src/core/runtime.rs`.

```penguin
if value > 0 {
    value -= 1
} else if value == 0 {
    value = 10
} else {
    value = 0
}

while value > 0 { value -= 1 }
loop { break }

for (var i = 0; i < 3; i += 1) {
    continue
}
```

`if`/`else if`/`else`, `while`, `loop`, C-style `for`, `break`, and `continue`
are defined in their respective `src/parser/parse_*_statement.rs` files and
generated in `src/generator/generate_loops.rs` and
`src/generator/generate_statement.rs`.

`match` compares each pattern by equality and accepts `else` only as the last arm:

```penguin
match code {
    200 { result = "ok" }
    404 { result = "missing" }
    else { result = "other" }
}
```

Defined in `src/parser/parse_match_statement.rs`; executed as comparisons and
jumps generated by `src/generator/generate_statement.rs`.

## Vectors, Objects, Types, and Modules

The name used in the code is **vector**, not array/list. Literals and indexing:

```penguin
var numbers = [10, 20, 30]
numbers[1] = 21
return numbers[1]
```

Defined in `src/parser/parse_vector_literal.rs` and `src/core/vector.rs`;
`GetIndex` and `SetIndex` are executed in `src/core/runtime.rs`. Indices accept
`int`, `uint`, or `byte` cells; negative values and out-of-bounds positions
produce an error.

Object literals are maps of fields that are mutable by default:

```penguin
var point = { x = 10, y = 20 }
point.x = 11
```

Defined in `src/parser/parse_object_literal.rs`, created by
`src/generator/generate_literal.rs`, and represented by `PengObject` in
`src/core/object.rs`.

Structured types declare fields and methods; construction uses `type:{ fields }`.
Module members use `:`; object attributes and method calls use `.`.

```penguin
type Point {
    var x: int
    var y: int

    func sum(self) -> int {
        return self.x + self.y
    }
}

var p = Point:{ x = 2, y = 3 }
var total = p.sum()
```

Structural inheritance is written as `type Child: Parent, Other { ... }`. Types,
construction, access, and calls are defined in
`src/parser/parse_type_declaration_statement.rs`, `src/parser/parse_expression.rs`,
`src/generator/generate_literal.rs`, and `src/generator/generate_expression.rs`.
The implementation should be considered experimental: custom compatibility is
structural, based on the fields of `PengCustomType` (`src/core/typing.rs`).

Modules contain declarations only:

```penguin
mod math {
    const two = 2
    func double(value) { return value * 2 }
}

var result = math:double(21)
```

Defined in `src/parser/parse_module_declaration_statement.rs` and
`src/core/module.rs`. In the current generator, the body of a function declared
inside a module does not directly resolve another member of the same module
(which is why the example does not use `two` inside `double`); this is an
observable limitation in `src/generator/generator_utils.rs`. There is no `import`
syntax in the lexer/parser of this repository.

## Operations and Operators

Operations are named binary callables, always with exactly two parameters. The
expression `left operation right` is recognized when the middle position is an
expression that resolves to `PengOperation`. Defined in
`src/parser/parse_operation_declaration_statement.rs`,
`src/parser/parse_expression.rs`, and `src/generator/generate_operation.rs`.

```penguin
oper combine(left, right) {
    return left + right
}

var result = 20 combine 22
```

Built-in operators inferred from the AST and opcodes:

| Category      | Operators                                |   |           |   |
| ------------- | ---------------------------------------- | - | --------- | - |
| arithmetic    | `+`, `-`, `*`, `/`, `**`, `%`            |   |           |   |
| concatenation | `..`                                     |   |           |   |
| comparison    | `==`, `!=`, `<`, `<=`, `>`, `>=`         |   |           |   |
| logical       | `!`, `&&`, `                             |   | `, `&`, ` | ` |
| assignment    | `=`, `+=`, `-=`, `*=`, `/=`, `**=`, `%=` |   |           |   |
| conversion    | `as`                                     |   |           |   |

`&&` and `||` short-circuit in the generator; `&` and `|` always evaluate both
sides. Defined in `src/parser/parser.rs`, parsed in
`src/parser/parse_expression.rs`, and generated in
`src/generator/generate_expression.rs`.

## `try`

`try expression` and `try expression else fallback` generate protected versions
of function/operation calls. A frame marked as `is_try` allows an error to be
recovered and produces the fallback value — or `nil` without `else`. Defined in
`src/parser/parse_expression.rs`, generated in `src/generator/generate_expression.rs`,
and recovered in `src/core/env.rs`. The parser restricts `try` to call forms
supported by the generator; treat it as an experimental feature.
